# Changelog for MishkaCmsBuilder 0.0.1

- Initial version: [mishka.tools/cms](https://mishka.tools/cms)
- The visual editor is its own package, split out of mishka_cms_core 0.0.3. It needs mishka_cms_core 0.0.4, mishka_gervaz 0.0.3 and mishka_installer 0.1.15 or later
- Two tests that raced the editor's async work now wait for it, so the suite no longer fails when the LiveView is slower than the test
- The release runs on Erlang 29.1.2 and Elixir 1.20.5, with the temporary OTP 29.0.5 pin removed
- `igniter_js` is 0.5.2 and every dependency is at its latest release, including `phoenix_html` 4.4.0, which fixes a security advisory
- Escape closes the Code window, Find, Settings, Examples, the reload and leave questions and the new-folder form without leaving their backdrop over the editor; the editor's keyboard hook leaves Escape to an open modal
- The Preview bar says Preview ▸ Open in a new tab comes once a draft is saved, instead of pointing to that entry before it exists
- The Desktop canvas lays the page out at least 1180px wide and scales it to fit, so it no longer shows the site's tablet layout; Tablet and Mobile scale down instead of running off a narrow canvas
- A `<.form>` and every other function component keep their class on the canvas, with the Inspector's styles merged in as on the published page; their `phx-*` bindings are still left out. A child of a parent whose class has `space-y-*`, `space-x-*` or `divide-*` is drawn as that parent's own child, not inside the editor's box, so a form's gaps match the preview: an `<.input>`'s own `mb-2` outranks the form's `space-y-4` on the canvas as on the page
- A required property left empty, or text where a component takes a list or a map, is named as what stops a publish: the Inspector says the page cannot be published without it, and the refusal reads "Not published —", since drafts, autosave and Code Apply still save it
- A drawer or `chelekom-sidebar` opened in place on the canvas takes its content's height instead of keeping `h-screen` and standing as tall as the viewport over the page, and stays in view instead of keeping the `-translate-x-full` (Tailwind v4's `translate` property) that slid a drawer, or a sidebar on a narrow device, off the canvas; a modal is drawn as before
- Custom CSS applied in Draft is written into the draft beside its markup (its `element_css`, with mishka_cms_core 0.0.5), so the new-tab draft preview, compiled from the draft on every open, shows it, and opening the draft after a reload of the editor brings it back to the canvas and the Custom CSS box. A named save holds it too, and the publish still writes it into the site's stylesheet row. The flash says "It is in the draft — the preview shows it; it goes live when you publish." With core 0.0.4 the rule stays held in the editing session until the publish, as before
- Selecting a slot in the layers rail, such as a sidebar's `<:item>`, rings the component it belongs to on the canvas, so an overlay opened in place stays open instead of snapping back to `fixed` and the full height of the screen
- ⌘Z and ⇧⌘Z while typing in inline text, a text field or the Code window's editor undo and redo the typing there, instead of undoing an earlier change to the page while the typed words stay on screen; with the focus anywhere else they still undo the page
- A `<textarea>` on the canvas holds its text as its value, as on the published page, instead of the editor's `<span data-node-id>` markup around it; an element dropped inside one is not drawn into it, and a `<title>` is drawn the same way
- An icon name the canvas cannot compute, such as `name={item[:icon]}` on `chelekom-icon` or core's `<.icon>`, stands in as `hero-sparkles` instead of an id-shaped `pb-<id>-name` that the icon's `"hero-" <> _` head refused, which logged "body did not apply" on every render before the palette arrived and drew a "could not render" box for `<.icon>`
- The ••• menu scrolls within the screen below the header, so on a short window its last entries (Command palette, Fit to screen, Record history) are no longer cut off
- The "body" crumb in the canvas bar drops the selection, as Escape does, instead of sending a select with no element and crashing the page and component builders
- An overlay on the canvas is opened on purpose, as in Elementor, Bricks, Oxygen and Webflow: its chip is a handle that a click selects (the Inspector shows its properties) and a drag moves, and "Open on canvas" in the Inspector's header or the pin on its layers row, now always in view, opens it in the flow where the chip stood until it is closed the same way, for this session only. A node inside a shut overlay selected from the layers rail, a slot included, still opens it. A sidebar that stays on the screen from a breakpoint up, such as `chelekom-sidebar` from `md` (`PaletteEntry.persistent_at/1`, `data-pb-persistent`), is edited where it sits at that width, with no chip, and is a drawer below it; the Inspector says "Always visible at this width — edit it on the page" there
- A required property written as an expression, such as `name={item[:icon]}` on `chelekom-icon` inside `chelekom-sidebar`, counts as filled on the canvas as it does at Publish (`Inspector.unmet/3`), so the canvas draws the component, an icon with its `hero-sparkles` stand-in, instead of a red "needs name" that Publish then accepted; one left out or blank is still drawn as needed and still refuses Publish, in the component builder as on a page
- A red dot with a count beside the saved dot in the top bar says what Publish would refuse: required properties left empty, required slots never added, text where a component takes a list or a map, a layout that no longer renders `@inner_content`, and markup that will not compile. It opens a window listing them by element, each under its breadcrumb, and a click closes it and selects that element on the canvas and in Layers with the Inspector on the property; one that will not compile opens the Code window. The dot, the window and the gate read one list, `BuilderLive.problems/1`, and a refused Publish says how many and each one ("Not published — 2 problems: …") and opens the same window. It is shown and hidden with `Phoenix.LiveView.JS` and marked `data-pb-modal` only while open, so Escape closes it
- A draft write that is refused is logged with its reason (`Logger.warning`) and named in the flash, "Can't be saved: …", instead of "Autosave is failing" with nothing in the log; the flash comes again only when the reason changes. A refusal flash shows only the error's words: an Ash error's header, breadcrumbs, refused value and stack trace are left out
- A drawer or other overlay opened on the canvas is drawn above a docked `fixed` sidebar beside it, with `z-index: 50` on its wrapper, instead of under it
- The Inspector's line under a required property left empty, or under text where a component takes a list or a map, names the document being edited: "the component cannot be published" in the component builder, and the layout or error page in theirs, instead of "the page" everywhere
- An icon typed into an icon box between braces, such as `{item[:icon]}`, is written as an expression, as HEEx reads it, instead of as the text `{item[:icon]}`; the box's hint for a name no set has says that `{…}` keeps an expression
- A refused Apply in the Code drawer leaves its error only while the document and the selection stay as they were, so an undo, another edit or another selection takes it away; and Apply and ⌘↵ stay available after a refusal, because the pane keeps the `data-dirty` that `PbCodeEditor` sets in the browser (`JS.ignore_attributes/1`) instead of losing it to the patch that draws the error
